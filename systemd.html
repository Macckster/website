systemd

Quick reference. Press / to filter.

Services

Start / stop / restart

sudo systemctl start myapp
sudo systemctl stop myapp
sudo systemctl restart myapp
sudo systemctl reload myapp

Enable at boot (and start now)

sudo systemctl enable --now myapp
sudo systemctl disable --now myapp

Status

systemctl status myapp
systemctl is-active myapp
systemctl is-enabled myapp
systemctl is-failed myapp

Prevent a unit from ever starting

sudo systemctl mask myapp
sudo systemctl unmask myapp

Reload after editing unit files

sudo systemctl daemon-reload

Inspect

List units

systemctl list-units --type=service
systemctl list-units --type=service --state=running
systemctl list-unit-files --state=enabled

What's broken?

systemctl --failed
sudo systemctl reset-failed

Show a unit file and its properties

systemctl cat myapp
systemctl show myapp
systemctl show myapp -p MainPID -p ActiveState

Dependencies

systemctl list-dependencies myapp
systemctl list-dependencies --reverse myapp

Boot performance

systemd-analyze
systemd-analyze blame
systemd-analyze critical-chain

Check a unit file for errors

systemd-analyze verify /etc/systemd/system/myapp.service

Journal (logs)

Logs for a unit

journalctl -u myapp
journalctl -u myapp -f
journalctl -u myapp -n 100 --no-pager

This boot / previous boot

journalctl -b
journalctl -b -1
journalctl --list-boots

By time

journalctl --since "1 hour ago"
journalctl --since today
journalctl --since "2026-10-01 09:00" --until "2026-10-01 10:00"

Errors only

journalctl -p err -b
journalctl -p warning..err -u myapp

Kernel messages

journalctl -k
journalctl -k -f

Jump to end / explain errors

journalctl -e
journalctl -xeu myapp

Output formats

journalctl -u myapp -o cat
journalctl -u myapp -o json-pretty
journalctl -u myapp -o short-iso

Disk usage & cleanup

journalctl --disk-usage
sudo journalctl --vacuum-time=2weeks
sudo journalctl --vacuum-size=500M

Unit files

Override part of a unit (drop-in)

Writes to /etc/systemd/system/myapp.service.d/override.conf and reloads for you. Add --full to edit a full copy instead.

sudo systemctl edit myapp
sudo systemctl revert myapp

Simple service

/etc/systemd/system/myapp.service

[Unit]
Description=My app
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=myapp
WorkingDirectory=/opt/myapp
ExecStart=/opt/myapp/bin/server --port 9000
Restart=on-failure
RestartSec=5
Environment=NODE_ENV=production
EnvironmentFile=-/etc/myapp/env

[Install]
WantedBy=multi-user.target

Hardening options

Add to [Service]. Check the result with systemd-analyze security myapp.

NoNewPrivileges=yes
ProtectSystem=strict
ProtectHome=yes
PrivateTmp=yes
ReadWritePaths=/var/lib/myapp
DynamicUser=yes

Unit file locations

/etc/systemd/system/        # yours (wins)
/run/systemd/system/        # runtime
/usr/lib/systemd/system/    # packages
~/.config/systemd/user/     # user units

Timers

List timers

systemctl list-timers --all

Timer unit (cron replacement)

/etc/systemd/system/backup.timer, which runs backup.service

[Unit]
Description=Nightly backup

[Timer]
OnCalendar=*-*-* 03:00:00
Persistent=true
RandomizedDelaySec=10m

[Install]
WantedBy=timers.target

Matching oneshot service

/etc/systemd/system/backup.service

[Unit]
Description=Nightly backup

[Service]
Type=oneshot
ExecStart=/usr/local/bin/backup.sh

Enable the timer, not the service

sudo systemctl daemon-reload
sudo systemctl enable --now backup.timer

Test an OnCalendar expression

systemd-analyze calendar "Mon..Fri 09:00"
systemd-analyze calendar --iterations=5 "*:0/15"

One-off delayed job

sudo systemd-run --on-active=30m /usr/local/bin/cleanup.sh
sudo systemd-run --on-calendar="2026-10-10 02:00" /usr/local/bin/migrate.sh

User services

Manage your own units

systemctl --user status myapp
systemctl --user enable --now myapp
journalctl --user -u myapp -f

Keep user services running after logout

sudo loginctl enable-linger $USER
