ssh

Quick reference. Press / to filter.

Keys

Generate a key

ssh-keygen -t ed25519 -C "you@example.com"
ssh-keygen -t ed25519 -f ~/.ssh/id_work -C "work"

Install your key on a server

ssh-copy-id user@host
ssh-copy-id -i ~/.ssh/id_work.pub user@host

Without ssh-copy-id

cat ~/.ssh/id_ed25519.pub | ssh user@host 'mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys'

Agent

eval "$(ssh-agent -s)"
ssh-add ~/.ssh/id_ed25519
ssh-add -l
ssh-add -D

Change passphrase / show fingerprint

ssh-keygen -p -f ~/.ssh/id_ed25519
ssh-keygen -lf ~/.ssh/id_ed25519.pub

Fix permissions

ssh silently ignores keys and config files that are too open.

chmod 700 ~/.ssh
chmod 600 ~/.ssh/id_* ~/.ssh/config ~/.ssh/authorized_keys
chmod 644 ~/.ssh/*.pub

Connecting

Basics

ssh user@host
ssh -p 2222 user@host
ssh -i ~/.ssh/id_work user@host

Run a command remotely

ssh user@host 'uptime'
ssh -t user@host 'sudo systemctl restart myapp'

Through a jump host

ssh -J user@bastion user@internal-host

Debug a connection

ssh -v user@host
ssh -vvv user@host

Host key changed / remove old entry

ssh-keygen -R host
ssh-keygen -R "[host]:2222"

Config file

~/.ssh/config

Then just: ssh web

Host web
    HostName 203.0.113.10
    User deploy
    Port 2222
    IdentityFile ~/.ssh/id_work
    IdentitiesOnly yes

Host internal
    HostName 10.0.0.20
    User deploy
    ProxyJump web

Defaults for every host

Put Host * at the bottom. The first value found wins.

Host *
    ServerAliveInterval 60
    ServerAliveCountMax 3
    AddKeysToAgent yes

Reuse connections (much faster reconnects)

Host *
    ControlMaster auto
    ControlPath ~/.ssh/cm-%r@%h:%p
    ControlPersist 10m

See the effective config for a host

ssh -G web

Tunnels

Local forward (reach a remote service locally)

localhost:5432 on your machine connects to db:5432 as seen from host.

ssh -L 5432:localhost:5432 user@host
ssh -L 5432:db.internal:5432 user@host

Remote forward (expose a local service on the server)

host:8080 connects to localhost:3000 on your machine.

ssh -R 8080:localhost:3000 user@host

SOCKS proxy

ssh -D 1080 user@host
curl --socks5-hostname localhost:1080 https://ifconfig.me

Tunnel in the background, no shell

ssh -fN -L 5432:localhost:5432 user@host

Escape sequences (type at start of line)

~.    # kill a frozen session
~C    # open command line, add forwards: -L 8080:localhost:80
~#    # list forwarded connections
~?    # help

Copying files

scp

scp file.txt user@host:/tmp/
scp user@host:/var/log/app.log .
scp -r ./dir user@host:~/
scp -P 2222 file.txt user@host:~/

rsync over ssh

The trailing slash on the source copies the contents rather than the directory itself.

rsync -avzP ./site/ user@host:/var/www/site/
rsync -avzP --delete ./site/ user@host:/var/www/site/
rsync -avzP -e "ssh -p 2222" ./site/ user@host:/var/www/site/

sftp

sftp user@host
# put / get / ls / lls / cd / lcd

Pipe a tarball

tar czf - ./dir | ssh user@host 'tar xzf - -C /opt'

Mount a remote directory

sshfs user@host:/var/www ~/mnt/www
fusermount -u ~/mnt/www

Server (sshd)

Harden /etc/ssh/sshd_config

Or drop a file into /etc/ssh/sshd_config.d/. Test that key login works before turning off passwords.

PermitRootLogin no
PasswordAuthentication no
KbdInteractiveAuthentication no
PubkeyAuthentication yes
AllowUsers deploy

Validate config, then reload

sudo sshd -t
sudo systemctl reload sshd

Change port (Fedora / SELinux / firewalld)

sudo semanage port -a -t ssh_port_t -p tcp 2222
sudo firewall-cmd --permanent --add-port=2222/tcp
sudo firewall-cmd --reload
# set "Port 2222" in sshd_config, then:
sudo systemctl restart sshd

Watch auth attempts

sudo journalctl -u sshd -f
sudo journalctl -u sshd --since today | grep -i failed

for f in /etc/ssh/ssh_host_*_key.pub; do ssh-keygen -lf "$f"; done
